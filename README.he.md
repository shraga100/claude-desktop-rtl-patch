# Claude Desktop RTL Patch

**תמיכה אמיתית בעברית ובערבית (כיווניות מימין לשמאל) ל-Claude Desktop ב-Windows.**

## ✨ מה זה עושה

- **מזהה אוטומטית טקסט בעברית ובערבית** בתשובות של Claude ובתיבת הקלט, ומיישר את הכיוון בזמן אמת, גם בזמן שתשובה עדיין נכתבת.
- **מטפל בקוד, בנוסחאות מתמטיות ובטבלאות** — בלוקי קוד ונוסחאות LaTeX (`$x^2$`, `$$…$$`) נשארים משמאל לימין בתוך עברית, וטבלאות עבריות נקראות מימין לשמאל.
- **מתקן את ממשק החלון שנשבר במערכות בכיווניות RTL** (פירוט בהערה למטה).
- **מגבה כל קובץ שהוא משנה**, עם שחזור בלחיצה אחת וחזרה אוטומטית למצב הקודם אם משהו משתבש.
- **נשאר מותקן גם אחרי עדכונים** (אופציונלי), דרך קיצור דרך בשולחן העבודה או רכיב עדכון אוטומטי שרץ ברקע.

**📝 הערה:** כשמערכת ההפעלה Windows מוגדרת לעברית או לערבית, כל ממשק החלון של Claude Desktop מתהפך לכיווניות RTL מעצמו. זה באג קיים שלא נגרם מהפאצ': כפתורי פס הכותרת (מזעור, הגדלה, סגירה) נדחפים אל מעל כפתורי ההגדרות והניווט של Claude ומסתירים אותם, וחלון התצוגה המקדימה קופץ לקצה השמאלי. הפאצ' מתקן את זה בכך שהוא מחזיר את כיווניות מסגרת החלון ל-LTR, בלי לפגוע בכיוון של טקסט השיחה עצמו.

## 🚀 התקנה מהירה

פתחו את **Windows PowerShell** והריצו:

<div dir="ltr">

```powershell
irm https://raw.githubusercontent.com/shraga100/claude-desktop-rtl-patch/main/install.ps1 | iex
```

</div>

תופיע בקשת UAC. לחצו **Yes** כדי לאשר הרשאות מנהל, ואז בחרו באפשרות **1. Install** מהתפריט.

**💡 טיפ:** מעדיפים לא להריץ דרך `iex`? הורידו את `patch.ps1` מהמאגר, לחצו עליו קליק ימני ובחרו **Run with PowerShell**.

## 🔄 לשמור על הפאצ' מותקן

מכיוון ש-Claude Desktop מתעדכן לעיתים קרובות, כל עדכון דורס את הפאצ'. שתי אפשרויות אופציונליות הופכות את התחזוקה לפשוטה:

- **קיצור Quick Update (אפשרות 3):** קיצור דרך בשם **Update Claude RTL**. לחיצה כפולה עליו מורידה ומחילה מחדש את הגרסה האחרונה, בלי להיכנס לתפריט.
- **עדכון אוטומטי (אפשרות 4):** משימה מתוזמנת קלילה של Windows. היא מזהה מתי Claude מתעדכן, מחילה את הפאצ' מחדש אוטומטית, ומציגה התראה בסיום. היא גם סוגרת תהליך שנשאר מהגרסה הקודמת ועלול למנוע מ-Claude להיפתח אחרי עדכון.

## 🔤 אופציונלי: פונט מותאם אישית

מעדיפים לקרוא בפונט אחר? הפאצ' יכול להציג את הטקסט של Claude בכל פונט **שכבר מותקן על המחשב**, ואתם בוחרים על איזה טקסט הוא יחול:

| היקף | מה משתנה | דוגמאות לפונטים |
| :--- | :--- | :--- |
| **כל הטקסט** | כל גליף (שאינו קוד) שהפונט מכסה | Rubik, Open Sans |
| **עברית בלבד** | אותיות עבריות; לטינית/ערבית לא מושפעות | Heebo, Rubik, Assistant |
| **ערבית/פרסית בלבד** (ברירת מחדל) | אותיות בכתב ערבי; לטינית/עברית לא מושפעות | [Vazirmatn](https://github.com/rastikerdar/vazirmatn), Noto Naskh Arabic |

### איך מפעילים, צעד אחר צעד

1. **מתקינים את הפונט** (פעם אחת, בלי אדמין): מורידים, מחלצים, מסמנים את **כל** קובצי ה-`.ttf`, קליק ימני → **Install**.
   - פרסית/ערבית — **Vazirmatn**: ה-`vazirmatn-vXX.XXX.zip` העדכני מ[דף ההורדות הרשמי](https://github.com/rastikerdar/vazirmatn/releases) (קובצי ה-`.ttf` תחת `fonts/ttf`).
   - עברית — **Heebo** / **Rubik** / **Assistant**: מורידים מ-[Google Fonts](https://fonts.google.com/).
2. **מריצים את המתקין** (ראו [התקנה מהירה](#-התקנה-מהירה) למעלה) ובוחרים **6. Set a Custom Text Font** מהתפריט.
3. מקלידים את שם משפחת הפונט — למשל `Vazirmatn` או `Heebo` — ומקישים Enter. אם השם לא נראה מותקן, המתקין יבקש להקליד שוב (או לאשר להשתמש בו בכל זאת).
4. בוחרים היקף: **1** ערבית/פרסית בלבד, **2** עברית בלבד, או **3** כל הטקסט.
5. עונים **Y** לשאלה *"?Apply the patch now"* (זה סוגר את Claude Desktop ומחיל את הפאצ' מחדש עם הפונט).
6. פותחים שוב את Claude Desktop. הטקסט שנבחר מוצג כעת בפונט שלכם; כל השאר ללא שינוי.

**לאוטומציה/סקריפטים**, אותה הגדרה זמינה גם כפרמטרים:

```powershell
.\patch.ps1 -CustomFont "Vazirmatn" -CustomFontScope arabic
```

`-CustomFontScope` מקבל `all`, `hebrew` או `arabic` (ברירת מחדל: `arabic`). הפרמטר הישן `-ArabicScriptFont` עדיין עובד.

### טוב לדעת

- הפאצ' לא מצרף ולא מוריד פונטים — הוא רק מפנה לפונט מותקן דרך `local()` ב-CSS. אם הפונט לא מותקן, שום דבר לא משתנה.
- **תחום ב-`unicode-range`:** בהיקף עברית או ערבית, אף כתב אחר לא מושפע. בלוקי קוד, מתמטיקה ופונטים של קוד (monospace) לעולם לא נדרסים — גם במצב "כל הטקסט".
- גליפים שהפונט לא כולל נופלים אוטומטית חזרה לפונטים הרגילים של Claude, כך שגם פונט עברי-בלבד במצב "כל הטקסט" לא מזיק.
- **נשמר:** הבחירה נשמרת (ב-`ProgramData\ClaudeRtlPatch`) ושורדת עדכונים אוטומטיים של הפאצ' אחרי עדכוני Claude — מגדירים פעם אחת ושוכחים.
- **כיבוי:** אפשרות 6 בתפריט → מקלידים `none` (או `.\patch.ps1 -CustomFont none`), ומחילים את הפאצ' מחדש.
- כל שם משפחה מאותיות/ספרות/רווחים/מקפים עובד, למשל `"Noto Naskh Arabic"`.

## 🛠️ פתרון תקלות

**מופיע `Node.js is required` או `is too old`:** התקינו או עדכנו את Node.js (גרסה 22.12 ומעלה) מ-[nodejs.org](https://nodejs.org/) ופתחו מחדש את PowerShell.

**אם Claude לא עולה אחרי ההחלה:** הריצו שוב את הסקריפט, בחרו **2 (Restore)** ואז **1 (Install)**.

**אם Claude התעדכן והפאצ' הפסיק לעבוד:** הריצו את קיצור **Update Claude RTL**, או השתמשו בעדכון האוטומטי. לתיקון ידני, מחקו את קבצי ה-`.bak` מתיקיית האפליקציה של Claude והריצו שוב את המתקין.

**אם Claude נעלם אחרי עדכון ולא נפתח שוב עד שסוגרים אותו במנהל המשימות:** ה-updater של Claude מתקין את הגרסה החדשה ברקע, אבל Windows עובר אליה רק אחרי שהגרסה הישנה נסגרת. לפעמים התהליך הישן נשאר ברקע בלי חלון, וכל הפעלה חדשה מעבירה אליו את השליטה ונסגרת מיד. עם העדכון האוטומטי (אפשרות 4), ברגע ש-Windows עובר לגרסה החדשה, ה-watcher סוגר את השארית תוך דקה, מחיל את הפאצ' מחדש ופותח את Claude. אם Claude לא חזר אחרי דקה-שתיים, סגרו ידנית רק את אפליקציית הדסקטופ (חלונות Claude Code CLI פתוחים לא ייפגעו) והפעילו את Claude שוב:

```powershell
Get-Process claude | Where-Object Path -like '*\WindowsApps\*' | Stop-Process -Force
```

אם לא נשאר אף תהליך של Claude והוא עדיין לא נפתח, התנתקו מהמשתמש והתחברו שוב (או הפעילו מחדש את המחשב). במקרה כזה Windows מחזיק container תקוע של האפליקציה ולא תהליך, כך שאין מה לסגור.

**מופיעה השגיאה `Import-Module … The member AuditToString is already present`:** הרצתם את הפקודה ב-**PowerShell 7 (`pwsh`)**, שיש בו באג ידוע ששובר את הפאצ'. השתמשו במקום זאת ב-**Windows PowerShell** המובנה:

1. הקישו **Win + R**, הקלידו `powershell` והקישו **Enter**. זה פותח את חלון Windows PowerShell ה**כחול** הקלאסי (לא את ה-`pwsh` השחור).
2. הדביקו את פקודת ההתקנה והריצו אותה.

<summary><b>🔍 איך זה עובד (טכני)</b></summary>

<div dir="rtl">

מכיוון ש-Claude Desktop היא אפליקציית Electron **חתומה דיגיטלית**, עריכה של קוד הממשק שלה שוברת את בדיקות השלמות. הפאצ' עוקף את זה בשלושה שלבים, כולם אטומיים ועם חזרה אוטומטית למצב הקודם בכל כשל:

**שלב 1, הזרקת ASAR.** הממשק של Claude נמצא בתוך `app.asar`. כלי Node קטן שמוטמע בסקריפט ([`src/asar-patch.cjs`](src/asar-patch.cjs)) עורך את הארכיון ישירות, בלי לחלץ ולארוז מחדש: הוא מוסיף לקבצי ה-renderer את ה-payload שמזהה RTL (וכופה את ממשק החלון ל-LTR בתהליך הראשי), מעתיק את שאר הקבצים כמו שהם, משאיר את המודולים המקומפלים ב-`app.asar.unpacked` מחוץ לארכיון, ובודק את רשומות ה-SHA-256 של כל קובץ לפני העריכה ואחריה. אחר כך הסקריפט מחשב לכותרת hash חדש. לוגיקת הזיהוי של ה-payload נמצאת ב-[`src/rtl-core.js`](src/rtl-core.js) (טהורה ונבדקת ביחידה) ו-[`src/rtl-payload.js`](src/rtl-payload.js) (שכבת ה-DOM); הסקריפט `tools/build-payload.ps1` מרכיב אותם, יחד עם הכלי, לתוך `patch.ps1`.

**שלב 2, החלפת ה-hash בתוך `claude.exe`.** ה-hash המקורי של ה-ASAR שמור כמחרוזת ASCII בתוך `claude.exe`. הסקריפט מבצע חיפוש-והחלפה ברמת הבייט כדי לעדכן אותו. אם הפורמט ישתנה אי-פעם, יש מנגנון גיבוי שמכבה את ה-Electron integrity fuse.

**שלב 3, החלפת התעודה בתוך `cowork-svc.exe`.** השירות הזה מאמת את `claude.exe` מול התעודה המוטמעת של Anthropic. הסקריפט מאתר אותה (לפי התאמת תבנית סביב המחרוזת `"Anthropic, PBC"`), מחליף אותה במקום בתעודה חתומה-עצמית (מרופדת ב-`0x00` כדי לשמר את גודל הקובץ), חותם מחדש את שני הקבצים, מוסיף את התעודה החדשה למאגר ה-trusted root של Windows, ואז מוחק את המפתח הפרטי.

כל הקבצים המקוריים מגובים כקבצי `.bak` ליד המקור לפני שמשהו משתנה.

<summary><b>🔐 אבטחה ואימות</b></summary>

<div dir="rtl">

הקובץ `install.ps1` מאמת חתימת **RSA-4096** על `patch.ps1` לפני שהוא מריץ אותו. מאגר GitHub פרוץ לבדו **אינו** מספיק כדי להפיץ קוד זדוני; התוקף היה צריך גם את המפתח הפרטי הלא-מקוון של המתחזק.

**טביעת אצבע של המפתח הציבורי (SHA-256):**

<div dir="ltr">

```
6e:f4:c2:a6:c2:42:34:a1:5f:e5:cd:e5:5d:a5:b0:3c:94:64:b4:56:7f:81:04:7c:83:9a:50:1c:7c:6f:07:c9
```

</div>

כדי לוודא, חשבו מחדש את טביעת האצבע של המפתח המוטמע ב-`install.ps1` ובדקו שהיא תואמת:
